# CLAUDE.md

Guide for Claude (and humans) working in this repo. The project owner mostly changes the game by asking Claude, so this file is the source of working rules.

## What this is

**Aethermoor** (working title): top-down real-time isekai fantasy action RPG, 2D vector graphics, open world, 8+ playable protagonists, single player, offline.
Two native clients with **separate code** and **shared data and specs**:

- `desktop/`: C++20, SDL3, with the in-house vector rasterizer (ADR 0012; ThorVG was dropped). Windows and Linux.
- `android/`: Kotlin, libGDX, the same rasterizer in Kotlin. Android 11+ (minSdk 30).

Full plan: `docs/plan/README.md` (Italian). Decisions: `docs/adr/`.

## Golden rules

1. **Spec first.** Gameplay rules are written in `docs/spec/` before or together with the code.
2. **Data driven.** Never hardcode names, texts, balance numbers or content in code. Content is JSON under `data/`; visible text only via `$i18n:` keys, always in `it` **and** `en`.
3. **Two clients, one behavior.** A change to rules touches: spec, reference (`tools/reference/`), conformance vectors, `desktop/`, `android/`. If a client lags, open a `parity-debt` issue and use a feature gate. Do not silently diverge.
4. **Never hand-edit** `tests/conformance/*.json`: regenerate with `tools/gen_conformance.py`.
5. **Determinism.** World generation uses only integer / Q16.16 math and the hash/PCG32 defined in the spec. No `float`, `sin`, `cos`, `pow`, `sqrt` there. Never use `-ffast-math`; keep `-ffp-contract=off` (GCC/Clang) and `/fp:strict` (MSVC).
6. **Gameplay math is integer** (percent and permille) plus data tables. No `pow` in formulas: use tables.
7. **Stable IDs.** `namespace:category/name`. Renaming an ID needs a save migration.
8. **No network, no telemetry, no secrets** in the repo (keystores, tokens).
9. **Licenses.** Code GPL-3.0-or-later, content CC BY-SA 4.0. Only add GPLv3-compatible dependencies.
10. **Core stays headless.** `core/data/sim/worldgen` must not import graphics, audio, input, UI or platform code.

## Repo map


## Commands

```bash
# Data validation (always before committing data/schema changes)
python tools/validate_data.py

# Regenerate the conformance vectors (parallel, about 20 s) and the stamps (quiet; --show draws them)
python tools/gen_conformance.py
python tools/make_stamps.py

# Generators of data from tables in code: run the one whose table you changed (the list is in tools/README.md)
python tools/make_recipes.py   # also make_gathering, make_companions, make_titles, make_prologues, make_sfx

# A catalog of the pack in tables (creatures, items, quests, sites), for reviewing the content
python tools/make_catalog.py   # writes docs/design/catalog.md

# A rough balance model (comfortable level per creature, from the formulas), to find outliers
python tools/balance_report.py   # writes docs/design/balance.md

# Ship a change in one go: checks, signed-off commit, push, PR, wait for CI, squash merge, refresh the play build
python tools/ship.py "feat: title" --body-file body.md --play <play folder>

# Desktop (needs CMake >= 3.28, Ninja, vcpkg; see docs/dev/setup.md)
cmake --preset windows-release     # or linux-release
cmake --build --preset windows-release
ctest --preset windows-release

# Android (needs JDK 17+, Android SDK; see docs/dev/setup.md)
cd android && gradle :core:test :app:assembleDebug
```

## Definition of Done

- [ ] Spec updated (`docs/spec/`) and ADR if architectural
- [ ] Data and schema updated; `python tools/validate_data.py` passes
- [ ] i18n keys present in `it` and `en`
- [ ] Conformance vectors regenerated if rules changed; tests pass on both clients
- [ ] Desktop and Android implemented, or `parity-debt` issue linked and feature gated
- [ ] `CHANGELOG.md` updated for user-visible changes
- [ ] Docs updated in the same PR

## Style

- C++: `PascalCase` types, `snake_case` functions/variables, `m_name_` members, `kConstant`, namespace `aether`. `clang-format` config in `desktop/.clang-format`.
- Kotlin: official style, ktlint + detekt. Package `io.github.progliodario.aethermoor`.
- JSON: 2 spaces, `snake_case` keys, `$schema` in every file, fractional values as integers (`_x100`, `_pm`).
- Commits: Conventional Commits, scope per area, `Signed-off-by` (DCO).
- Branches: `feat/...`, `fix/...`, `docs/...`, `content/...`, `chore/...`. Squash merge.

## How to work

- **Full autonomy.** The owner has delegated every design decision (story, tone, balance, content) and wants Claude to do all the work without asking: decide, implement, ship, and keep going down the roadmap (`docs/plan/06-roadmap-rischi-backlog.md`, section 8). A question now and then is fine when a choice is truly the owner's taste, but never wait on one: pick the best option, say what was chosen, go on. Only publishing and governance stay with the owner (a public release, branch protection, repository settings, licenses of outside material, code signing).
- **Fights must be too easy.** The protagonist is overpowered, as in every isekai: this is a core theme, not a balance bug. Tune the creatures and the world so that ordinary fights are won in a blow or two and guardians are a show, not a wall. Never make the game harder to make it "balanced".
- Before a multi-file change, state the plan and the list of files.
- **Who tests what.** This machine has no C++ or Kotlin compiler: CI is the only build. The owner play-tests every change in depth on Windows, Linux and Android and reports what is wrong; the owner never edits files or runs tools. Still report honestly what was run and what was not (e.g. "desktop not built locally", "not seen on screen").
- Tests of both clients count what the data holds (stamps, static people, tiles of the tileset, the gids of the start tile): grep `desktop/tests/` and `android/core/src/test/` and update them in the same change as the data, or CI fails.
- A script whose strings hold a backslash (such as `\n`): create it with the Write tool, not with a shell heredoc (it loses the backslash).
- Prefer small PRs, one concern each. Spec/format changes go alone.

## Common tasks

- **Add enemy / item / skill / quest / place / region:** follow [`docs/guides/add-content.md`](docs/guides/add-content.md): copy the closest file in `data/base/`, follow its schema in `schemas/`, add i18n keys (it+en), run the validator, regenerate the vectors and the catalog (`tools/gen_conformance.py`, `tools/make_stamps.py`, `tools/make_catalog.py`).
- **Add protagonist:** follow the section "A protagonist" of [`docs/guides/add-content.md`](docs/guides/add-content.md) and [spec 18](docs/spec/18-protagonists.md).
- **Change a rule:** `docs/spec` → `tools/reference` → `tools/gen_conformance.py` → desktop → android.
- **Add a language:** new folder `data/base/i18n/<lang>/`, add it to `pack.json` languages.

## Slash commands (`.claude/commands/`)

`/validate`, `/spec-change`, `/parity-check`. More are planned (`/add-enemy`, `/add-quest`, `/add-protagonist`, `/release`).

## Where things stand

Eight protagonists (Ren, Sakura, Daichi, Haruka, Marco, Yuki, Lena, Gideon: spec 18), a streamed 16384 x 16384 world with eight regions, 36 hand-made sites (with Fenwick, the home village, and Aldermere, the guild town, hand-written by `tools/make_towns.py`), 60 creatures, 145 items, 166 quests (with the first two acts of each protagonist's story, written by `tools/make_stories.py` and `tools/stories_act2.py`), guild, shops, inns, stones, seasons, three save slots with export and import, Italian and English. Combat has elements, status effects (on creatures and on the player), parry, dodge and stagger; there are companions (stay/follow, bond), gathering, crafting (16 recipes), a bestiary, 15 titles (each adds attack), four talents (a point a level; `tools/make_talents.py`), a shared `profile.json` with echoes, and a prologue for each protagonist. Sound effects are on; the music (no `music_rules.json`) and the regional ambience (empty `ambience.regions` in `events.json`) are switched off because the owner found them unpleasant: do not turn them back on without asking (see `docs/design/catalog.md` and the status of `docs/plan/06-roadmap-rischi-backlog.md`, section 8). Feature gating exists (ADR 0009) but is not used yet: `supported_features` is empty in `project.json` and in both clients, and parity is kept by the shared specs and vectors. The world difficulty is `enemy_hp_pct` 100 and `enemy_atk_pct` 70 (easy on purpose); the map reveals 5 x 5 cells around the player.
