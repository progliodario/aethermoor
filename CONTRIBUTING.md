# Contributing

Thanks for helping. This project has **two native clients** (C++ desktop, Kotlin Android) that share **specs and data**. Please read `CLAUDE.md` for the working rules; they apply to humans too.

## The four rules

1. **Spec first.** A gameplay rule lives in `docs/spec/`. Change the spec in the same PR as the code.
2. **Data driven.** No game text, names or balance numbers in code. Content goes in `data/`, strings in `data/**/i18n/` (Italian **and** English).
3. **Two clients.** A feature is done when spec, data, tests, desktop **and** Android are done. If one client lags, open a `parity-debt` issue and gate the feature.
4. **Parity is tested.** Shared conformance vectors in `tests/conformance/` are generated by `tools/`, never edited by hand.

## Workflow

1. Open or pick an issue. For rule changes use the `spec_change` template.
2. Branch from `main`: `feat/<area>-<short>`, `fix/...`, `docs/...`, `content/...`, `chore/...`.
3. Commit with [Conventional Commits](https://www.conventionalcommits.org/): `feat(desktop): ...`, `fix(data): ...`.
   Scopes: `desktop`, `android`, `data`, `spec`, `docs`, `tools`, `ci`, `art`, `audio`, `ui`, `i18n`.
4. Sign off every commit (`git commit -s`): this is the [DCO](https://developercertificate.org/). No CLA.
5. Run `python tools/validate_data.py` and the tests of the area you touched.
6. Open a PR using the template and tick the checklist. Squash merge.

## Languages

- Code, file names, commits, technical docs (`docs/spec`, `docs/dev`): **English**.
- Design docs (`docs/design`) and the main README: **Italian**.
- In-game text: Italian and English, always together.

## Content rating

The target rating is PEGI 12 / Teen: stylized violence, all characters adult, no explicit content. See `docs/plan/03-game-design.md`.
